# 老師資格同步與本機 QA 殘留整理

## 使用者可見的規則

- 員工的「啟用」與「獲准授課」是兩個獨立設定，管理員在員工的「編輯排課資料」修改。
- 時間表老師篩選、新排課、可約時段的新老師指派只採用啟用且獲准授課的員工。登入角色不決定授課資格；管理員可以同時授課，老師也可以沒有登入帳戶。
- 舊資料沒有資格欄位時，沿用原有授課資格，以保留既有四位老師。新增老師表單會明確顯示「獲准授課」勾選項。
- 停用或取消資格後，既有課堂及報名保留；目前檢視日期範圍內的未來課堂若仍有該指派，課表顯示覆核提示。既有指派可保留作一般編輯，複製或新建指派則不能重新使用失效資格。
- 不再把課堂中的舊文字名稱自動當成新的老師清單來源。公開可約時段遇到已停用或取消資格的老師時停止提供預約。

## 維護操作

從專案根目錄執行。先使用目前程式啟動服務以更新資料庫結構；不要重新 seed 或重設帳戶。

```sh
# 只列計劃，不修改資料。路徑須明確指定。
node scripts/archive-extra-demo-data.mjs --database sample/.data/beamal.sqlite
# 套用；backup 必須是未存在的新目錄，會包含 before.sqlite 與 attachments/。
node scripts/archive-extra-demo-data.mjs --database sample/.data/beamal.sqlite --apply --backup sample/.data/backups/qa-cleanup-20261019
# 還原前先列出；加 --apply --backup <另一個新目錄> 才會實際還原。
node scripts/archive-extra-demo-data.mjs --database sample/.data/beamal.sqlite --restore
```
