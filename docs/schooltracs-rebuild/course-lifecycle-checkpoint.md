# 課程可還原刪除／還原：服務檢查點

日期：2026-10-14（香港時間）。本檢查點記錄本機共用測試服務的實作及隔離 HTTP 測試結果；前端、打包及真正瀏覽器結果由統籌核實後另行補記。這不是正式部署或整頁完成證明。

## 原系統已觀察與 Beamal 暫定決定

SchoolTracs 已直接觀察到 Courses 的 **Normal／Deleted** 選單，切到 Deleted 後為 **No deleted course yet**，以及 **Edit course → Delete／Save**。沒有在原系統按 Delete 或完成 Restore，沒有保存後的關聯資料證據。詳見 [補充研究](research-courses-followup.md)。

Beamal 為保留既有資料，本輪採用**可還原刪除**：只標記刪除狀態，不移除課程或實體檔案；有未刪除排課時拒絕刪課。已刪課程須先還原，才能再新增或還原排課。這些是 **Beamal 的暫定業務保護規則**，不是已確認的 SchoolTracs 保存／刪除行為，不能描述成一模一樣。

## 本輪服務範圍

- 管理員可刪除／還原課程；老師可讀取保留資料，不能修改；學生不能操作生命週期 API。
- 管理員／老師的 course list 及 catalog 保留已刪課程，刪除記錄多出 `deletedAt` 時間；未刪記錄的原有資料格式保持不變。畫面如何在 Normal／Deleted 切換，屬前端待驗收範圍。
- 刪除／還原保留同一個課程 ID、`courseCode`、首次建立時間、費用 ID／價格／連結、教材、附件及稽核歷史；只更新課程版本、最後修改時間及刪除狀態。
- 有未刪除排課時回覆 `409 COURSE_HAS_SCHEDULES`；已刪除排課不阻擋刪課，但不能繞過課程刪除狀態直接還原排課。
- 已刪課程不可修改基本資料，亦不可新建排課、教材、上載或費用關聯；回覆 `409 COURSE_DELETED`。已存在費用可保留原有已刪課程連結並修改資料，不會因此失去歷史關係。
- 已刪課程名稱仍保留唯一性；同名建立回覆 `409 COURSE_NAME_DELETED`，讓介面引導還原原課程，避免建立替代編號。
- 學生 catalog／courses 隱去已刪課程。學生 fees 隱去其關聯 ID；一項費用若只連到已刪課程亦不列出，混合關聯則只提供仍有效的課程 ID。管理端的原有費用資料及關聯保留。
- 已有課程教材授權的學生，在刪課後不能讀取直接教材、附件預覽或下載網址，服務回覆 404。老師／管理員仍可讀取保留內容。還原後原有授權與教材可見設定重新生效，不刪除或重建授權。
- 新授權不可指向已刪課程；服務重啟時可重複確認原本已存在的授權，避免啟動程序誤把它當成新增權限。

## API 與保存保護

| 操作 | 請求 | 成功回覆 |
| --- | --- | --- |
| 刪除課程 | `DELETE /api/courses/:id`，JSON `{version}` | 200 `{course}`，包含 `deletedAt` |
| 還原課程 | `POST /api/courses/:id/restore`，JSON `{version}` | 200 `{course}`，不再包含 `deletedAt` |

兩者須有真正管理員登入、合法來源及防偽識別（CSRF token）。只接受目前版本，拒絕額外欄位；版本過舊或缺少版本回覆 409。可使用固定 `Idempotency-Key`：相同使用者、路徑、識別碼及內容的重試回覆同一份結果，不重複增加版本或稽核記錄。

課程狀態、版本、最後時間、稽核記錄及重試收據放在同一筆資料庫交易內：任何一步失敗均回滾，不保留半份刪除結果。排課及新關聯檢查也使用同一份共用資料庫；沒有整份上傳或覆寫瀏覽器的舊預覽資料。

重要實證：

- 同一課程刪除後，另一管理員讀到相同 ID、courseCode、版本及費用。關閉資料庫後，以原有教材授權設定重開服務，刪除狀態、費用、教材及重試回覆仍在；還原沒有建立替代課程或費用。
- 真正 PNG 檔案上載並連到學生可見教材。刪課後學生的 inline／download 請求均為 404；老師仍取得相同 bytes；還原後學生再次取得同一份 bytes，沒有重上載或刪除檔案。
- 未刪排課擋住刪課；先刪排課後可刪課；課程仍刪除時還原排課被拒，先還原課程後相同排課 ID 才能還原。
- 五個並行相同刪除請求只產生一次版本變更及一筆刪除稽核。相同版本的刪除／修改競爭，只接受一方，不靜默覆蓋另一方。
- 在隔離 SQLite 加入故障觸發器，令刪除稽核寫入失敗；檢查課程狀態／版本摘要不變、沒有重試收據。移除故障後，同一操作識別碼可成功重試。
- 本輪修改／新增的服務及測試檔案均通過 `node --check`。沒有執行 Git、瀏覽器或實際資料操作。
