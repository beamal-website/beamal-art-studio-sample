# Beamal 完整測試管理系統

## 已確認的最後成果

以 SchoolTracs 的功能、欄位、業務規則和操作流程作參考，保留現有 Beamal 美術風格，完成可多人使用的完整測試管理系統。付款及通知使用測試模式。中英文切換和手機版均屬必要功能。

這份規格記錄 2026-10-14 本次對話已確認的要求。參考網站內部程式及伺服器設計未公開；我們會重建查證到的操作效果，未能查證的行為須列為待確認。

## 完成條件

- 真正獨立帳戶登入、角色權限及共用資料；不同使用者、瀏覽器和裝置讀到正確資料。
- 盤點參考系統所有頁面、子頁、彈窗及功能，逐項研究、實作及驗證；不把停用按鈕或外觀完成視作功能完成。
- 課程、收費、排課、學生、報名、訂單、測試付款、出席、套票和報表等資料連動正確。
- 付款使用可驗證的測試交易，通知使用測試渠道；具備結果、錯誤及記錄，並不處理真實款項。
- 中英文、手機、鍵盤操作、錯誤回饋、取消及返回行為一致；保留現有 Beamal 圖片和美術風格。
- 搜尋、切頁、拖動及表單操作流暢；用較多資料驗證效能，保存測試環境、資料量和結果。
- 有可使用的網站、可接手的程式與啟動說明，以及研究和逐項驗收紀錄。
- 所有已定義功能均有驗收證據；不存在未處理的重要問題或未核准的功能缺口。

## UI／UX 及流暢度驗收

- 在桌面及實際 390 像素寬度核對中英文；表單沒有標籤重疊或頁面橫向溢出，主要操作容易找到。較闊的資料表可以在表格內橫向捲動。
- 開啟表單有清楚焦點，鍵盤不會跳到背景；取消／關閉後返回原按鈕。輸入、取消、返回及儲存結果均可辨認。
- 儲存時即時顯示進行中並阻止重複操作；失敗保留已填資料，成功直接顯示服務確認的結果。網絡延遲、重試或登入過期不導致重複建立或錯誤覆寫。
- 多人同時修改、背景更新及切換帳戶都須實測；更新不破壞未完成表單，離開表單後顯示最新清單。
- 速度驗收保存資料量、環境、回應時間中位數及較慢的 95% 分位數，以及實際瀏覽器操作結果。服務讀取快不等於畫面操作已通過；大量資料須驗證搜尋、切頁、表格及拖動，重要卡頓先修正再進下一頁。

## 工作方式

1. 主 Agent 統籌範圍、依賴、整合及向使用者交代結果。
2. Research Agent 逐項操作 SchoolTracs，保存實際觀察及未測事項。同一時間只有該 Agent 操作參考網站。
3. 製作 Agent 根據研究結果實作指定部分；共用程式同一時間由一位 Agent 修改。
4. 獨立驗證 Agent 對照相同步驟驗證原系統與我們的系統，包含跨頁、資料保存、權限、錯誤情況、手機及效能。
5. 當頁通過後自動前進；重要差異、無法測試或需要使用者決定的規則才提出問題。

## 第一個工作單元

Courses／Fees：先研究清單、建立及修改、三種收費、期限與套票等規則，確認目前版本與參考系統的差異。同時建立真正帳戶及共用資料的必要基礎，使此頁的驗收能涵蓋跨使用者保存和後續報名計價。

後續依賴：Timetable → Students／Enrollment → Sales／Orders → Accounting／Reports；Products、Leads、Staffs、Messages、Channels、Settings 等按依賴安排。這不是排除其他頁面的範圍清單；完整盤點會在研究紀錄內逐項補全。

### 本次最新優先次序

使用者因時間有限，明確要求先放下目前教材／PDF 的延伸問題，並再澄清課程和時間表高度相關，集中完成 **課程＋時間表 → 產品 → 學生 → 會計 → 報告 → 員工**。兩頁須使用同一課程及排課資料，作為聯合主流程驗收。即時採用此工作次序；保留已做改動及其驗證，未完成項目記錄為待辦，不把跳過當成驗收通過。先做好各頁主要操作、共用保存及中英文／手機效果，完成必要功能檢查；完整系統目標仍保留。

使用者最新要求先停新增功能，完成一次中期 SchoolTracs 功能對齊及異常檢查。結果見 `MIDTERM-CHECK.md`；發現的重要問題修正及重新驗收前，不進入 Products 功能製作。這是進行中的品質檢查，不是取消或完成完整 Goal。

重要功能繼續核對 Chrome 的 SchoolTracs。使用者授權略過較次要但複雜的功能（包括部分外部跳轉及進階附件功能）；重要操作與資料保存不能只因複雜而略過。每個略過項目記錄理由、影響及是否已有部分完成，保存於 `DEFERRED.md`，最終向使用者列完整清單。沒有驗證的原系統行為仍標為待確認。
