# 正式課堂的試堂及調堂連動 — 待核對方案

狀態：使用者已確認方案；實作及本機驗證完成。
日期：2026-10-20（香港）

## 目標及操作效果

既有正式課堂可直接接受試堂和調堂，不必另外新增同時間的獨立 Available Time。管理員及獲分派該堂的老師能在該堂詳情頂部開關用途和設定名額；網站、學生端及老師端使用同一份課堂資料。

## 名額計法（本方案的明確假設）

- 正課名額：輸入這堂正常收生的名額，例如 6。
- 勾選「允許試堂」後，顯示必填的試堂名額，例如 2。
- 勾選「允許調堂」後，顯示必填的調堂名額，例如 1。
- 總容量由系統計算：6＋2＋1＝9；使用者不另填總容量。
- 未開放的用途不計入總容量，也不提供新的預約入口。
- 畫面分別顯示名額上限、已用名額、剩餘名額。不能將「上限」當作已經有多少位學生。
- 新的預約必須同時通過該用途名額、實際總容量及資格檢查。待處理但已保留的名額也要計算，兩名使用者同時搶最後一位不能超收。
- 關閉用途或降低名額若影響已有預約，阻止儲存並說明原因；不能靜靜刪掉申請或取消學生安排。

例子：正課 6 位已收滿，試堂名額 2 位尚未使用，調堂名額 1 位尚未使用，仍可接受 2 位試堂及 1 位調堂。正課收滿不能誤判整堂已無這兩類名額。

## 設定層次與位置

### Course：建立及編輯課程

增加「課堂名額預設」區域，包含正課名額、兩個用途開關及對應名額、計算出的總容量。

這些是新增正式課堂的起始值，不是將所有既有課堂強制改成同一設定。更改 Course 預設只影響之後新建的排課；已建立及已獨立調整的課堂維持原狀。

### Add Schedule／新增正式課堂

套用所選 Course 預設，容許在儲存前修改。選完開關才顯示該用途的名額欄位，總容量即時計算。建立後各次課堂均沿用建立當刻的設定。

重複排課不會變成一堆無法追溯的重複獨立活動；仍保留原本排課及每堂序號，另儲存該堂的用途設定與必要例外。

### Time slot／單堂詳情

頂部、課堂一般資料之前顯示：

```
試堂及調堂名額
正課名額     6
[✓] 允許試堂     試堂名額 [2]
[✓] 允許調堂     調堂名額 [1]
總容量       9
[還原修改] [儲存]
```

開關和輸入屬草稿，按儲存才影響三端。只更改目前這一堂，不會連帶更改同系列前後課堂。儲存後顯示已用／剩餘名額。未勾選的用途不展示無關詳細資料。

有預約而無法停用時保留原有資料及開關，顯示易明原因。兩個人同時修改時，要求載入最新設定，不能以舊資料蓋過他人儲存。

手機版上下排列，保留中英文；不使用老師代表色作視窗頂部裝飾邊。

## 三端連動

### Public website

- 開放試堂且符合公開條件的正式課堂，直接進入該 Course 試堂清單，提供正常的 Choose／申請流程。
- 不另建同日期時間的獨立 Available Time；網站不重複顯示同一堂。
- 滿額是否顯示沿用公開課表現有設定；已停用、已取消、課程下架、無合資格老師等情況不能接新預約。
- 不把調堂名額、學生個人資料或內部備註公開。

### Student portal

- 在原有調堂申請流程列出正式課堂可用的調堂名額。
- 必須有剩餘名額並符合原課、學生、日期等既有資格規則。不能因顯示新開關而繞過資格或付款／課堂權益檢查。
- 沿用原有待審批／已批准流程。未批准申請不能冒充已成功調堂。
- 批准後學生課堂、調堂記錄、原堂及新堂人數一致。

### Teacher portal／Course

- 獲分派該堂的老師看到該堂正課、試堂、調堂學生，清楚標示類別及申請／安排狀態。
- 待審批與已安排分開顯示，避免老師誤以為待審批學生必定到堂。
- Course 下 Trials／Rescheduling 清單與單堂詳情使用伺服器確認的剩餘名額，不自行用簡化計算取代真正可預約名額。
- 老師只可修改自己獲分派課堂的用途及名額；不能因此獲得其他課程、其他老師或整體排課的修改權。
- 原有通知、待辦、學生申請及審批記錄沿用，避免建立第二套互不連通的申請。

## 舊資料及保障

- 舊 Course 及舊排課沒有新設定時維持現有功能；不批次自動開放試堂或調堂。
- 已存在、連接正式課堂的 Available Time 保留原 ID、版本、預約、申請、審批及來源關係；不能再為同一堂製造另一組名額。
- 原有獨立 Available Time 仍可使用，與正式課堂分清來源。
- 資料變更須可追溯、原子儲存（同一次操作全部成功或全部不寫入）、有版本及重試保障。
- 實際本機資料更新前備份；不可影響 main 或擅自推送。

## 已檢查的現況與改動範圍

1. `sample/server/schedules.mjs`：目前正式排課只有單一 capacity，並有單堂／往後課堂修改機制；新增用途設定不能破壞原本例外。
2. `sample/server/available-slots.mjs`：已有 linked source、試堂／調堂獨立名額、預約及停用限制；新功能應整合原有來源和預約，不再建立另一套。
3. `sample/server/class-capacity-status.mjs` 及 `sample/server/rescheduling-availability.mjs`：目前會按正式班 capacity 和人數截斷可調堂名額；需要同新名額模型一致，避免正課收滿後錯誤隱藏額外預留名額。
4. `sample/server/trial-applications.mjs`：沿用正式試堂申請及保留名額流程。
5. `sample/src.js`、`sample/client/`：Course、新增排課、單堂詳情及三端畫面。
6. `sample/shared/`：必要的名額與單堂設定規則，避免前後端分別實作不同算法。

不指定以大量預先建立 Available Time 的方式處理無限重複排課；正式設計必須支援按日期查詢及單堂例外，避免無上限新增記錄。

## 技術慣例

沿用 Vite、原生 JavaScript、既有 SQLite／PostgreSQL 支援，不新增框架或套件。數字必須是整數；啟用用途需要正數名額；驗證與權限必須在伺服器再次檢查。

沿用現有驗證寫法，例如：

```js
if (!Number.isSafeInteger(capacity) || capacity < 1) {
  throw new ApplicationError(400, 'INVALID_CAPACITY', 'Choose a positive whole number.');
}
```

測試在 `sample/tests/` 與 `sample/server/tests/`，使用現有 Node test runner。

## 分段實作及驗收

1. **名額及單堂資料**：先驗證正課＋試堂＋調堂總容量、舊資料相容、單堂例外、已有預約保護與多人同時預約。
2. **Course／新增排課**：預設值帶入、用途欄位顯示、總數即時計算、建立後不被後續預設覆蓋。
3. **單堂控制與權限**：詳情頂部操作、只改一堂、自己的老師權限、無關老師及學生拒絕修改。
4. **網站／學生端**：公開試堂清單及申請、學生調堂選項及批准，名額和權益一致。
5. **老師端與整體核對**：正課／試堂／調堂名單、待辦與課堂記錄一致，中英文及手機排版驗證。

## 可直接執行的檢查

```sh
npm test --prefix sample
npm run build --prefix sample
```

每一段先跑對應測試，完成後再跑整體測試及打包。瀏覽器至少核對以下例子：

- 正課 6＋試堂 2＋調堂 1：顯示總容量 9；正課滿後兩類額外名額仍可使用。
- 重複排課三堂，只把第二堂試堂改為 1；第一及第三堂維持 2。
- Course 預設更改後，既有三堂名額不變，新建排課沿用新預設。
- 最後一個試堂／調堂名額被同時申請，只允許一個成功保留。
- 已有試堂／調堂預約後關閉用途或降至低於已用名額：拒絕操作，資料保留。
- 同一堂不會因為已有 linked Available Time 而重複顯示／重複提供名額。
- 老師端看得到該堂相應學生及狀態，無關老師不能修改或看到未獲授權的資料。
- 網站沒有內部調堂或學生資料；學生不能看到不合資格的調堂選項。

## 邊界

- 一定做：保留既有記錄、驗證權限與名額、更新相關測試、以 test 開發、按功能分段保存。
- 另行確認才做：回填並自動開放舊課堂、整批覆蓋單堂設定、改變既有預約／審批政策、刪除已預約的時段。
- 絕不做：刪除預約來避開限制、繞過名額及學生權益檢查、建立第二套申請、修改 main、擅自 push。

## 實作紀錄

- 重複排課按查詢日期產生穩定的單堂來源 ID，儲存單堂設定或真正預約時才落實記錄，支援無限重複排課而不預先產生無限資料。
- Course 預設儲存於內部課程資料，建立排課時快照；既有 linked Available Time 優先，保留其 ID 及預約。
- 單堂開關只儲存該次課堂。正課名額沿用正式排課；調整正課名額可由原有修改課堂入口操作。
- 學生調堂選項沿用原有查詢範圍與資格規則；預設查詢會產生未來一年內的新正式課堂來源，明確日期查詢則跟隨該日期。
- 瀏覽器測試已確認正式課堂試堂出現於網站；測試課堂已還原原本未開放的設定。
