111 項來源狀態為 **92 已確認、9 待細化、9 待討論、1 暫緩**。核心清單為 41／0／6／1，操作清單為 51／9／3／0；兩份合起來才是完整 111 項。這些數字從來源分類得出，不是完成比例。每項最終另列「尚未實作／部分／已測／待決策／明確暫緩」及證據。

本輪最終資料規模是 **4 位老師、300 名 active 學生、6 個課程、3–18 歲**。用虛構測試資料及合理歷史記錄建立可重開的本機測試庫；不讀取或搬入私人學生資料。人數／課程數不是硬性上限；3–18 歲是本輪規模分布，不自行當成全部註冊的拒絕政策。課名、適齡、價格、課包及課室均可維護，不把主文「約 10 課」或示例 4／8／12／24 堂寫死。

交付是**本機網站＋本機共用服務＋同一份持久資料**。不同管理員、老師、家庭／學生帳戶可以完成角色內流程；中英文、手機、鍵盤及 Beamal 圖片／風格均保留。付款、郵件、App 通知及訊息用可追蹤的測試模式，不能稱真 FPS 到帳、真郵件送達或真家長已收到。

遠端伺服器部署、SEO、native iOS 本輪先不製作。規格內「App／多端」的已確認業務要求，本輪先由相同身份的本機網頁流程及第二瀏覽器／分頁驗證；保留同一 API、資料及權限邊界，日後再接真正 App。這不等於 iOS 或外部部署已驗收。

## 不能跳過的依賴關係

1. **身份與資料範圍先於每個資料入口。** 授課資源不是登入帳戶；Admin 可同時授課，普通老師只見自己／授權資料。列表、詳細、附件、搜尋、事件與寫入都須服務端核對，Filter 只能改畫面。
2. **班次與個別學生課次分開。** 系列 ID＋固定 sequence 可沿用；Class Session、Student Session、Attendance、個別 Pending、Staff Leave、文字 Remark 各自有狀態，不能讓某學生 Pending 改全班或因缺席釋位。
3. **正式班額、TrialQuota、ReschedulingQuota 分開。** 配額／資格在最終 Submit 或 Confirm 再核對，並和申請／安排／待辦一起保存；競爭最後一位時不能只靠禁按鈕。失敗全部不變，重試只處理一次。
4. **Request／Payment／Convert 分開。** Confirm Request 只核對項目／應付額，Confirm Payment 才令課程正式生效；Convert 始終人工獨立。兩種先後順序都須能關聯同一個人，不能重建檔案、重復入班／入帳。
5. **事件與所有相關端一起驗。** 共用保存回覆、版本與事件去重可沿用；每 5 秒刷新只是目前機制，不能冒充已完成即時通知。服務重開後持續 To-do／到期提醒不能消失。
6. **視覺不是資料事實。** 老師主色、學生貼紙、Available／Full 紅綠點獨立；公開／隱藏不改時段名稱、日期、名額及資格；內部任意 1–14 天和公開 7–30 天是不同設定。

## 每階段的證據格式與最終檢查

每項需求至少記錄：**ID、來源版本、實作範圍、虛構資料、操作步驟、預期／實際結果、正常與失敗證據、相關待決事項**。使用「服務端測試／前端流程測試／實際瀏覽器／效能／本機重開恢復」分欄；其中一種通過不能替代其餘證據。

- 服務與資料：隔離測試庫的真HTTP測試，未登入／錯身份／越範圍／舊version、同時最後名額、相同與不同重試key、丟回覆、交易回滾；業務唯一約束避免另一key重複付款／佔位。
- UI與流程：真入口、正確字段、未保存草稿的Cancel/Escape/Browser Back、錯誤保留輸入、保存ACK、新舊身份/晚回覆/後台刷新；長文、合成照片及名稱一律安全顯示。
- 跨頁及角色：管理員兼授課、不同老師/授權、不同家庭/學生、第二管理員/分頁；課程/費用/產品/名單/課次/付款/通知/報表都來自相同權威記錄，不能只有一個界面更新。
- 本機保存與恢復：關閉服務再開資料仍在；遷移、私有附件、測試單據、事件游標、提醒與權限保存；獨立備份還原驗證數據庫與文件一起可恢復。
- 流暢度：記4/300/6及歷史量、環境、讀/寫次數、響應中位數和95%分位數、實際瀏覽器搜索/翻頁/選擇/輸入/拖動、390手機與較寬桌面結果。先量測再定合理改進門檻，不能憑人數猜快慢。
- 必要命令：功能更改後完整 `npm test --prefix sample` 及 `npm run build --prefix sample`，保存本次結果；相關範圍修改另做有意義回歸及獨立review。文檔／純文案更改不為了增加測試數去寫鏡像測試。
