# 老師、課室與排課連動檢查點

日期：2026-10-14–15。這是課程＋時間表中期檢查的下一個切片，並非 Staffs 全頁、Notion 全規格或完整 Goal 已完成。

## 這輪的實際效果

- 管理員可在時間表的「老師及課室」建立、搜尋、修改及停用排課資料；課室另有容量、詳細資料、備註及外部地點。
- 同一堂課可指派多位老師及多間課室。指派保存穩定 ID，名稱只是顯示；改名後原有篩選、詳情與課程內排課仍指向同一筆資料。
- 一堂有兩位老師仍只是一堂，不會因多選而倍增。老師人數按已指派資料計算；尚未接入的正式學生／付款人數仍顯示「—」，不冒充零人。
- 停用不刪歷史指派；新課堂／新指派不能使用已停用資料。修改舊課堂時間可以保留原本已停用的指派，複製為新課堂則須重新選擇啟用資料。
- 舊版只有文字的老師、課室保留為未配對資料，不能按同名自動綁到其他人；使用者可明確選正式資料或清除舊指派。
- 新增老師資料不開登入帳戶、不邀請任何人；這與完整員工資料、授課帳戶連結、薪酬、請假及代課是不同功能。

## 保存與錯誤處理

資源及課堂均經本機共用 HTTP 服務與 SQLite 保存。新增／修改使用操作識別碼防止丟回覆後重試重複建立；修改包含開啟時的版本，衝突或權限失敗保留輸入。晚到的舊讀取及舊身份回覆不能蓋過已保存資料或關閉新身份的表單。

老師／課室的同類名稱重複保護、停用及版本衝突是 Beamal 保護規則。SchoolTracs 的名稱衝突、停用／還原、資源衝突及容量限制效果尚未完整核對，不宣稱這些規則與來源相同。來源多選證據只到表單選取，沒有保存多選課堂，詳見 [資源研究](research-scheduling-resources.md)。

## 獨立檢查與修正

- 複製課堂原本漏帶 teacherIds／roomIds，只剩顯示文字，正式指派無法直接複製。獨立測試先重現失敗，再修正為複製 ID 陣列；新複製不能套用「保留舊已停用指派」的例外。
- 名稱排序可能令同一選取集合從 A＋B 變成 B＋A；若誤判為更改指派，「只改往後時間」會蓋掉後續單堂的不同老師／課室。獨立真 HTTP 重現後，服務以成員集合辨認同一指派並保留開啟順序與名稱快照；建立與真正更換成員仍保留明確輸入。
- 前端亦按同一成員集合保留開啟時的 ID 次序，不能由勾選框在頁面上的排序暗改指派；真正選取不同成員仍保存新選擇。舊資料省略 IDs 與明確送空陣列清除保持不同。
- 資源儲存期間所有控制項停用時，Tab 仍須被視窗攔截；已加入零控制項的處理與回歸。
- 沒有資料變動的每5秒背景讀取原本仍重建資源視窗，可能丟掉按鈕焦點或捲動。獨立測試先證明多餘重繪，再修正為只在資料／載入／錯誤狀態改變時更新；編輯草稿仍不被背景更新取代。
- 「關閉資源管理後是否立即更新底層名稱」獨立回歸直接通過：原有 renderModal 已處理待顯示的共用更新，不需要另加修正；不把排查假設記成已證實問題。
